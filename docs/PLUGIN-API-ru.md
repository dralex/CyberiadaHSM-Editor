# Интерфейс плагинов

**Версия документа:** 0.4 (2026-10-15), контракт плагинов `api` 1. Оригинал на английском
языке: `PLUGIN-API.md`.

Документ предназначен для авторов плагинов. Плагин добавляет редактору
CyberiadaPro новое действие — проверить диаграмму, сгенерировать код, скомпилировать,
нарисовать — без изменения самого редактора. Обычно плагин пишут и упаковывают авторы
инструмента, который он запускает, в репозитории этого инструмента; кроме того, любой
может упаковать плагин для чужого инструмента или положить плагин в свою пользовательскую
папку плагинов. Внутреннее устройство редактора описано в `PLUGINS.md`.

Плагин — это каталог с дескриптором `plugin.json`. При каждом запуске редактор записывает
копию активного документа во временный каталог запуска, запускает там объявленную
команду, ждёт её завершения и забирает результат, объявленный действием.

```
 редактор                                             плагин
+------------------------------+                    +------------------------------+
| пишет каталог запуска:       |  argv, env         | читает  ${input}             |
|   input.graphml              |  cwd = каталог     |         ${request}           |
|   request.json (если нужен)  | -----------------> |         ${param-file:x}      |
|   файл на каждый param-file  |                    |                              |
|                              |                    | выполняет свою работу        |
| показывает stdout и stderr   | <-- stdout, stderr |                              |
| читает объявленный результат | <-- код завершения | пишет   ${output}            |
|                              |                    |         ${diagnostics}       |
|                              |                    |         файлы в ${outdir}    |
+------------------------------+                    +------------------------------+
```

## Минимальный плагин

```
hello/
    plugin.json
    size.py
```

```json
{
  "api": 1,
  "id": "hello",
  "name": "Hello",
  "interpreter": "python3",
  "actions": [
    { "id": "size", "label": "Document size", "result": "log",
      "argv": ["${plugin_dir}/size.py", "${input}"] }
  ]
}
```

```python
import os
import sys
print(os.path.getsize(sys.argv[1]), 'bytes')
```

Положите `hello/` в пользовательскую папку плагинов (см. «Упаковка») и перезапустите
редактор: в меню Plugins появится пункт «Document size»; щелчок по нему выводит размер
во вкладку «Вывод Hello» (Hello output) панели плагинов.

## Каталог плагина

```
<папка плагинов>/<id>/
    plugin.json        дескриптор, UTF-8
    icons/*.svg        значки меню и панели инструментов (необязательно)
    ...                скрипты, адаптер, поставляемые модули
```

* Имя каталога должно совпадать с `id` плагина; учитывается `id` из `plugin.json`.
* `id` соответствует `[a-z0-9][a-z0-9._-]*` и не меняется: под ним хранятся сохранённые
  значения параметров. Называйте плагин по инструменту (`hsm-ros2`, `lapki-compiler`).
* Пути внутри дескриптора задаются относительно каталога плагина или через
  `${plugin_dir}`.

## plugin.json

```json
{
  "api": 1,
  "id": "hsm-maker",
  "name": "HSM Maker",
  "version": "0.1.0",
  "description": "Draws a new diagram from a description; sends it to an LLM service",
  "icon": "icons/maker.svg",
  "interpreter": "python3",
  "env": { "PYTHONPATH": "${plugin_dir}" },
  "parameters": [ ... ],
  "actions": [ ... ]
}
```

| Поле | Обязательно | Значение |
|---|---|---|
| `api` | да | старшая версия контракта, `1`; дескриптор с неизвестной редактору старшей версией пропускается |
| `id` | да | идентификатор плагина (см. выше) |
| `name` | да | имя в меню и в менеджере плагинов |
| `version` | нет | собственная версия плагина, показывается в менеджере плагинов |
| `description` | нет | подсказка и текст в менеджере плагинов; укажите здесь, если плагин обращается к сети |
| `icon` | нет | значок плагина (SVG или PNG) |
| `interpreter` | нет | логическое имя интерпретатора (`python3`); команда тогда — `interpreter + argv` |
| `env` | нет | дополнительные переменные окружения; значения могут использовать `${plugin_dir}` |
| `parameters` | нет | параметры, общие для действий (см. «Параметры») |
| `actions` | да | хотя бы одно действие |
| `session` | нет | зарезервировано для протокола сессий уровня 2; в `api` 1 не учитывается |

Действие:

| Поле | По умолчанию | Значение |
|---|---|---|
| `id` | обязательно | идентификатор действия, уникальный в плагине; `--run-plugin <плагин>:<действие>` |
| `label` | обязательно | текст пункта меню; заканчивайте его на `...`, если действие запрашивает ввод |
| `result` | обязательно | `replace`, `new-document`, `diagnostics`, `files` или `log` (см. «Результаты») |
| `argv` | обязательно | команда: список строк с переменными и условными элементами (см. «Командная строка») |
| `exit_ok` | `[0]` | коды завершения успешного запуска |
| `timeout` | `60` | секунды; `0` — без ограничения |
| `parameters` | все | идентификаторы параметров, которые действие использует и показывает |
| `outdir` | нет | идентификатор параметра `dir` (или `file`), получающего файлы; обязателен для действия `files` |
| `load` | `{}` | `strict`: отвергать вывод, не соответствующий стандарту строго; `reconstruct`: строить раскладку вывода без геометрии |
| `save` | `false` | сохранить изменённый или безымянный документ перед запуском, чтобы `${document}` был актуален (для безымянного запрашивается имя) |
| `cwd` | `"run"` | рабочий каталог: `run` (каталог запуска) или `document` (каталог документа; подразумевает `save`) |
| `toolbar` | `false` | поместить действие на панель инструментов плагина |
| `meta` | нет | метаинформация, с которой работает действие, например `{"platformLanguage": "Python"}`; заполняется, если в документе её нет (см. «Метаинформация») |
| `icon` | значок плагина | значок действия для панели инструментов и меню |
| `description` | нет | подсказка |

## Как редактор показывает плагин

* **Меню «Плагины» (Plugins)** — подменю с именем плагина и его действиями; оно завершается
  пунктом «Параметры...» (Settings...), если у плагина есть хранимые параметры; плагин с
  одним действием и без хранимых параметров — это один пункт меню.
* **Панель инструментов плагина** — действия с `toolbar: true` образуют небольшую панель с
  именем плагина справа от основной панели инструментов; пользователь может её скрыть.
* **Щелчок** — если у действия есть параметры `run`, параметр `document`, ещё не заданный
  для этого документа, или обязательный параметр `persistent` без значения, редактор
  открывает диалог, построенный по этим параметрам; иначе действие сразу запускается с
  сохранёнными значениями.
* **Панель плагинов** — у каждого плагина своя вкладка вывода «Вывод <имя>» (<name>
  output) со stdout и stderr его запусков; пользователь закрывает её, очищает или
  сохраняет в текстовый файл. Вкладка «Замечания» (Diagnostics) содержит замечания; у
  работающего плагина есть кнопка «Отменить» (Cancel).

```
+--------------------------------------------------+
| HSM Maker - Draw a new diagram               [x] |
+--------------------------------------------------+
| Description                                      |
| +----------------------------------------------+ |
| | A traffic light with a pedestrian button;    | |
| | the yellow light blinks at night.            | |
| +----------------------------------------------+ |
| Model      [deepseek-flash                    ]  |
| Server     [https://api.deepseek.com/v1       ]  |
| API key    [env:DEEPSEEK_API_KEY              ]  |
|                                 [Cancel]  [Run]  |
+--------------------------------------------------+

+--------------------------------------------------+
| ROS2 package - Make the package              [x] |
+--------------------------------------------------+
| Package directory [~/work/light/ros      ] [...] |
|                                 [Cancel]  [Run]  |
+--------------------------------------------------+
```

Сам плагин не открывает окон и ничего не спрашивает через stdin: всё, что ему нужно,
объявляется параметрами, поэтому то же действие выполняется и в пакетном режиме.

## Командная строка

Команда — это `interpreter + argv` или только `argv`; без интерпретатора `argv[0]` — это
программа относительно каталога плагина или найденная в `PATH`; в Windows программе без
расширения соответствует и `<имя>.exe`, а файл `.bat` или `.cmd` программой быть не
может. Оболочки (shell) нет: каждый элемент списка — один аргумент, кавычки не нужны, а
подставленное значение повторно не раскрывается. stdin — пустое устройство (null device).
Окружение — окружение редактора, плюс `env`, плюс экспортированные секреты, плюс
`CYBERIADA_PRO_LANGUAGE` — язык интерфейса.

Элемент argv может быть условным: `{"if": "<параметр>", "argv": [...]}` добавляет свои
строки, когда параметр равен `true` (для bool) или не пуст (для любого другого типа), и
ничего не добавляет в противном случае.

```json
"argv": ["${plugin_dir}/check.py", "${input}", "${diagnostics}",
         {"if": "strict", "argv": ["--strict"]}]
```

| Переменная | Значение |
|---|---|
| `${input}` | `<rundir>/input.graphml`: активный документ в формате CyberiadaML-GraphML 1.0, включая несохранённые правки; пустой файл для пустого документа |
| `${output}` | `<rundir>/output.graphml`: куда действие `replace` или `new-document` записывает документ |
| `${diagnostics}` | `<rundir>/diagnostics.json`: куда записываются замечания |
| `${outdir}` | значение параметра `outdir` действия; каталог запуска, если его нет |
| `${rundir}` | временный каталог запуска; удаляется после запуска |
| `${plugin_dir}` | каталог плагина |
| `${request}` | `<rundir>/request.json`, записывается только если argv его использует |
| `${param:x}` | значение параметра `x`; bool — `true` или `false` |
| `${param-file:x}` | файл в каталоге запуска со значением `x`; используйте его для длинных текстов, например промптов |
| `${meta:k}` | значение метаинформации документа: `platform`, `platformVersion`, `platformLanguage`, `markupLanguage`, `name`, ...; пусто, если отсутствует |
| `${selection}` | идентификаторы выделенных элементов в порядке документа через запятую (редактор выделяет один элемент за раз) |
| `${language}` | язык интерфейса редактора: `en`, `ru`, ...; `en` в пакетном режиме |
| `${document}` | файл документа на диске; пусто для безымянного; актуален только с `save` |
| `${document_dir}`, `${document_name}` | его каталог; его базовое имя без расширения |

Неизвестная переменная приводит к ошибке запуска ещё до старта. Символ `$`, за которым не
следует `{`, остаётся как есть.

Имя интерпретатора разрешается по настройкам редактора («Настройки», Preferences), затем по `PATH`; в
Windows для `python3` пробуются также `python` и `py -3`, а заглушка Microsoft Store
пропускается. Редактор для Windows не содержит Python: плагин на Python остаётся там
отключённым с подсказкой, пока интерпретатор не найден.

## request.json

Плагин с большим числом входных данных может читать один файл вместо аргументов. Файл
записывается, если argv содержит `${request}`:

```json
{
  "api": 1,
  "plugin": "hsm-maker",
  "action": "draw",
  "editor_version": "1.0.0",
  "language": "ru",
  "input": "/tmp/cyberiada-plugin-Xa12/input.graphml",
  "document": { "path": "/home/user/work/light.graphml", "format": "cyberiada",
                "modified": true },
  "meta": { "platform": "ArduinoUno", "platformVersion": "1.0",
            "platformLanguage": "C++" },
  "selection": ["n3", "t7"],
  "params": { "prompt": "A traffic light with a pedestrian button",
              "model": "deepseek-flash" },
  "outputs": { "output": "/tmp/cyberiada-plugin-Xa12/output.graphml",
               "diagnostics": "/tmp/cyberiada-plugin-Xa12/diagnostics.json",
               "outdir": "/tmp/cyberiada-plugin-Xa12" }
}
```

`document.format` — формат, в котором сохраняется документ (`cyberiada`, `yed-ostranna`,
`yed-berloga`); вход всегда в формате CyberiadaML-GraphML 1.0. `meta` содержит строки
метаинформации документа, кроме собственного состояния вида редактора. Секретов в файле
нет никогда.

## Результаты

| `result` | Плагин записывает | Редактор |
|---|---|---|
| `replace` | весь изменённый документ в `${output}` | заменяет документ одним шагом отмены «Plugin: <label>» |
| `new-document` | документ в `${output}` | открывает его как изменённый безымянный документ: в активной вкладке, если она пустая и безымянная, иначе в новой вкладке |
| `diagnostics` | `${diagnostics}` | показывает замечания |
| `files` | файлы в `${outdir}` (параметр `outdir` действия) | перечисляет новые и изменённые файлы во вкладке вывода |
| `log` | stdout, stderr | ничего больше |

* Выходной документ может быть в формате CyberiadaML-GraphML 1.0 или в диалекте yEd,
  который читает библиотека; документ сохраняет собственный формат сохранения.
* Вывод без геометрии принимается при `load.reconstruct`: редактор строит раскладку сам.
  Без этого флага записывайте геометрию.
* Вывод `replace` сохраняет идентификаторы неизменённых элементов, чтобы выделение и
  замечания продолжали указывать на них. Вывод, совпадающий со входом, ничего не меняет.
* Нечитаемый или пустой вывод означает неудачный запуск; документ остаётся прежним.
* Любое действие может также записать `${diagnostics}`; действие `replace` может так
  сообщить, что именно оно изменило.
* Действие `replace` недоступно, пока редактор находится в режиме инспекции, а на время
  его выполнения документ блокируется.

## Файл диагностики

```json
[
  { "severity": "warning", "rule": "CGML-6.9-4-4", "element": "nMeta", "line": 31,
    "message": "transitionOrder 'transitionFirst' is not admissible" },
  { "severity": "info", "rule": "CGML-6.4-4-2", "element": "G0", "line": 28,
    "message": "state machine 'G0' contains no initial pseudostate" }
]
```

| Поле | Обязательно | Значение |
|---|---|---|
| `severity` | да | `error`, `warning` или `info`; принимаются и числа LSP 1-4 |
| `message` | да | одна строка для пользователя; переводы строк показываются пробелами |
| `rule` | нет | идентификатор правила или требования |
| `element` | нет | идентификатор узла, ребра или машины состояний; щелчок по записи выделяет элемент |
| `line` | нет | строка файла `${input}` |

Прочие поля не учитываются; файл, не являющийся таким массивом, означает неудачный
запуск. `element`, отсутствующий в документе, показывается без ссылки. Записи становятся
серыми, как только документ меняется после запуска. Формат — подмножество `Diagnostic` из
LSP: severity 1 — это `error`, 2 — `warning`, 3 и 4 — `info`, `code` соответствует `rule`.

## Параметры

```json
"parameters": [
  { "id": "prompt", "type": "text", "label": "Description", "scope": "run",
    "required": true, "language": "markdown" },
  { "id": "model", "type": "string", "label": "Model", "scope": "persistent",
    "default": "deepseek-flash" },
  { "id": "dir", "type": "dir", "label": "Package directory", "scope": "document",
    "default": "${document_dir}/ros", "create": true },
  { "id": "key", "type": "secret", "label": "API key", "scope": "persistent",
    "export": "HSM_MAKER_KEY" }
]
```

Общие поля: `id`, `type`, `label`, `default`, `scope` (по умолчанию `run`), `required`
(по умолчанию `false`), `description` (подсказка).

| `type` | Виджет | Опции | Значение |
|---|---|---|---|
| `string` | строка ввода | | текст |
| `text` | большое текстовое поле в верхней части диалога | `language`: подсветка по правилам редактора (`markdown`, `python`, ...) | текст с переводами строк; передавайте его через `${param-file:x}` |
| `int`, `double` | поле со счётчиком | `min`, `max` | число |
| `bool` | флажок | | `true` или `false` |
| `enum` | выпадающий список | `choices`: список строк | выбранная строка |
| `file` | строка ввода с `...` | `filter` (`"Python (*.py)"`), `save`: выбор нового файла | путь |
| `dir` | строка ввода с `...` | `create`: создать отсутствующий каталог | путь |
| `secret` | строка ввода со значением `env:NAME` или `file:PATH` | `export`: переменная, получающая ключ | — (никогда не попадает в argv) |

| `scope` | Когда запрашивается | Где хранится |
|---|---|---|
| `run` | при каждом запуске, начиная со значения по умолчанию | не хранится |
| `persistent` | один раз; меняется в окне «Параметры...» | для пользователя |
| `document` | при первом запуске для файла документа; меняется в окне «Параметры...» | для пользователя и файла документа |

* Значения хранятся в настройках редактора и никогда — в диаграмме.
* `default` может использовать `${document_dir}` и `${document_name}`, чтобы каталог
  предлагался рядом с диаграммой; для безымянного документа они пусты, и такое значение по
  умолчанию тоже пусто. Можно использовать и `${language}`, чтобы параметр языка следовал
  за интерфейсом.
* Секрет разрешается в начале запуска — переменная `NAME` окружения редактора или первая
  строка файла `PATH` — и экспортируется вашему процессу в переменной `export`. Он никогда
  не попадает в argv, `request.json`, вкладку вывода или настройки. Не выводите его.

## Перевод

Тексты `plugin.json` пишутся на английском языке. Плагин переводит их отдельным файлом на
каждый язык, `i18n/<язык>.json`: это соответствие английского текста его переводу.

```
hsm-to-python/
    plugin.json
    i18n/ru.json
```

```json
{
  "HSM to Python": "HSM в Python",
  "Check the code": "Проверить код",
  "Tick, ms": "Такт, мс",
  "update": "обновить"
}
```

* При поиске плагинов редактор читает файл своего языка интерфейса (он выбирается в
  настройках и применяется при запуске) и переводит имя и описание, подписи и описания
  действий и параметров, а также показываемые варианты выбора; значение варианта не
  меняется.
* Текст без перевода показывается как написан, ключ, не совпадающий ни с одним текстом,
  не учитывается, а файл, не являющийся объектом JSON, выводится как предупреждение.
* Пакетный режим — английский и переводы не читает.
* Собственные сообщения плагина могут следовать тому же языку: запуск получает его как
  `${language}`, как `CYBERIADA_PRO_LANGUAGE` и как `language` в `request.json`.

## Метаинформация

Действие может объявить метаинформацию, с которой оно работает:

```json
{ "id": "check", "label": "Check the code", "result": "diagnostics", "save": true,
  "meta": { "platformLanguage": "Python" }, "argv": [ ... ] }
```

* Перед запуском, а для действия с `save` — и перед сохранением, редактор заполняет каждый
  отсутствующий в документе ключ, всё одним шагом отмены; запуск уже видит значение
  (`${meta:k}`, сохранённый файл).
* Имеющийся в документе ключ сохраняет своё значение; отличающееся значение отмечается во
  вкладке вывода, и запуск продолжается. Язык платформы считается тем же под любым своим
  именем (`python3`, `Python`).
* Документ без машины состояний или документ только для чтения не изменяется.
* Результат `replace` или `new-document` несёт метаинформацию в самом документе.

## Коды завершения, ошибки, отмена

* Запуск успешен, если код завершения входит в `exit_ok`, а объявленный вывод существует и
  читается. Всё остальное означает неудачный запуск: пользователь видит код завершения и
  конец stderr, документ не изменяется.
* Пишите ход работы и сообщения в stdout, а ошибки — в stderr, в кодировке UTF-8; они
  появляются во вкладке вывода плагина по ходу запуска, до 1 МиБ за запуск. Плагин на
  Python в Windows задаёт `PYTHONUTF8=1` в `env`, чтобы писать UTF-8 в канал (pipe).
* Тайм-аут или кнопка «Отменить» завершают процесс (SIGTERM в Unix) и через 3 секунды уничтожают
  его; в Windows рассчитывайте на уничтожение. Останавливается только ваш процесс:
  останавливайте сами процессы, которые вы запустили, например локальный сервер.
* `CYBERIADA_PRO_PLUGIN_KEEP=1` в окружении редактора сохраняет каталоги запуска для
  отладки.

## Тестирование плагина

Пакетный режим запускает действие без окна и без диалогов; значения берутся по умолчанию
и из опций `--plugin-param`.

```
# в репозитории инструмента: папка . содержит editor-plugin/plugin.json
CyberiadaPro --batch --plugin-path . --list-plugins
CyberiadaPro --batch light.graphml --plugin-path . \
    --run-plugin hsm-ros2:generate --plugin-param dir=/tmp/ros --dump
CyberiadaPro --batch --plugin-path . --run-plugin hsm-maker:draw \
    --plugin-param prompt=@light.txt --plugin-param key=env:DEEPSEEK_API_KEY \
    --save light.graphml
```

| Опция | Значение |
|---|---|
| `--run-plugin <id>[:<действие>]` | запустить действие; `:<действие>` можно опустить, если у плагина оно одно |
| `--plugin-param <имя>=<значение>` | значение параметра, можно повторять; `<имя>=@<файл>` читает значение из файла, `@@` означает ведущий символ `@`; bool — `true` или `false`; секрет принимает `env:NAME` или `file:PATH` |
| `--plugin-path <каталог>` | искать плагины только в `<каталоге>`, можно повторять; относительно текущего каталога; работает и в графическом режиме |
| `--list-plugins` | вывести найденные плагины, их состояние и причину, по которой плагин отключён или отвергнут; документ не нужен |
| `--dump-plugin` | вывести только разделы `== plugin` и `== diagnostics` |

Без документа в командной строке запуск начинается с пустого документа, что подходит для
действия `new-document`. `--dump` добавляет раздел `== plugin` (действие, состояние, код
завершения, ваш stdout, файлы) и раздел `== diagnostics`; без дампа ваш stdout идёт в
stdout редактора. stderr всегда идёт в stderr редактора. Папки называются по
происхождению (`plugin-path 1`, `env 1`, `user`, `system`), а не по пути, поэтому вывод
одинаков на любой машине. Код завершения: 0 — успешный запуск (с замечаниями или без),
1 — ошибка использования (неизвестный плагин, отсутствующее или недопустимое значение),
6 — неудачный запуск.

## Упаковка

Устанавливайте каталог плагина как есть, вместе с `i18n/`:

| Система | Папка |
|---|---|
| Linux, системная | `<prefix>/share/cyberiada-pro/plugins/<id>/` — префикс редактора, `/usr` для пакета Debian |
| Linux, пользовательская | `~/.local/share/Cyberiada/CyberiadaPro/plugins/<id>/` |
| Windows, zip-архив редактора | `<папка редактора>\share\cyberiada-pro\plugins\<id>\` |
| Windows, пользовательская | `%APPDATA%\Cyberiada\CyberiadaPro\plugins\<id>\` |
| macOS, пользовательская | `~/Library/Application Support/Cyberiada/CyberiadaPro/plugins/<id>/` |
| macOS, пакет приложения | `CyberiadaPro.app/Contents/share/cyberiada-pro/plugins/<id>/` |

* Храните каталог в репозитории инструмента как `editor-plugin/` и устанавливайте его из
  пакета инструмента или из небольшого отдельного пакета (`<инструмент>-editor-plugin`),
  если инструмент не должен знать о редакторе.
* Пакет Debian объявляет `Enhances: cyberiada-pro` и зависит от того, что запускает
  плагин (`python3`, сам инструмент).
* Пользовательский плагин перекрывает системный плагин с тем же `id`.
* Обновление заменяет каталог. Сохранённые значения сохраняются, пока идентификаторы
  параметров не меняются; переименованный параметр начинает со значения по умолчанию.
* Повышайте `api` только тогда, когда редактор документирует новую старшую версию; новый
  редактор продолжает выполнять перечисленные им старшие версии.

## Примеры

### Проверка диаграмм через cgmlval

Средство проверки из `cyberiadaml-compat-tests` пишет собственный JSON, поэтому плагин
содержит небольшой адаптер; пакет кладёт модуль `cgmlval` рядом с ним.

```json
{
  "api": 1,
  "id": "cyberiada-checker",
  "name": "Diagram checker",
  "version": "0.1.0",
  "description": "Checks the document against CyberiadaML-GraphML (PNST 1044-2025)",
  "interpreter": "python3",
  "env": { "PYTHONPATH": "${plugin_dir}" },
  "actions": [
    { "id": "check", "label": "Check", "result": "diagnostics",
      "toolbar": true, "icon": "icons/check.svg",
      "argv": ["${plugin_dir}/check.py", "${input}", "${diagnostics}"] },
    { "id": "strict", "label": "Check (strict)", "result": "diagnostics",
      "toolbar": true, "icon": "icons/strict.svg",
      "argv": ["${plugin_dir}/check.py", "${input}", "${diagnostics}", "--strict"] }
  ]
}
```

```python
#!/usr/bin/env python3
"""The diagram checker plugin: cgmlval findings to editor diagnostics."""
import json
import re
import subprocess
import sys

ID = re.compile(r'\[id=([^\]]+)\]')


def main():
    graphml, diagnostics, options = sys.argv[1], sys.argv[2], sys.argv[3:]
    run = subprocess.run([sys.executable, '-m', 'cgmlval', 'validate', '--json']
                         + options + [graphml],
                         stdout=subprocess.PIPE, universal_newlines=True)
    if run.returncode not in (0, 1):    # 2: cgmlval could not read the file
        return 2
    entries = []
    for report in json.loads(run.stdout):
        for finding in report['findings']:
            entry = {'severity': finding['severity'].lower(),
                     'rule': finding['req'],
                     'message': finding['message'],
                     'line': finding['line']}
            ids = ID.findall(finding.get('path', ''))
            if ids:
                entry['element'] = ids[-1]
            entries.append(entry)
    with open(diagnostics, 'w', encoding='utf-8') as out:
        json.dump(entries, out, ensure_ascii=False, indent=1)
    print('{} finding(s)'.format(len(entries)))
    return 0


if __name__ == '__main__':
    sys.exit(main())
```

Замечания, показанные выше в разделе «Файл диагностики», — это вывод данного адаптера для
тестовой диаграммы редактора `tests/diagrams/choice.graphml`.

### Генератор пакета ROS2

`hsm_robot_ros_generator` принимает диаграмму и выходной каталог; адаптер не нужен.
Каталог запоминается для каждой диаграммы.

```json
{
  "api": 1,
  "id": "hsm-ros2",
  "name": "ROS2 package",
  "description": "Generates the hsm_controller ROS 2 package; needs ROS 2 and pysm",
  "interpreter": "python3",
  "parameters": [
    { "id": "dir", "type": "dir", "label": "Package directory", "scope": "document",
      "default": "${document_dir}/ros", "create": true, "required": true }
  ],
  "actions": [
    { "id": "generate", "label": "Make the package...", "result": "files",
      "outdir": "dir",
      "argv": ["${plugin_dir}/hsm_generator.py", "${input}", "-o", "${outdir}", "-f"] }
  ]
}
```

Инструмент, который читает дополнительные файлы рядом с диаграммой (`hsm-to-python`
встраивает файлы, названные в диаграмме), задаёт `"cwd": "document"` и использует
`${document}` вместо `${input}`.

### Рисование диаграмм с помощью LLM

`cybersphere-hsm-maker` создаёт новую диаграмму по описанию. Описание передаётся через
файл, ключ — через экспортированную переменную.

```json
{
  "api": 1,
  "id": "hsm-maker",
  "name": "HSM Maker",
  "version": "0.1.0",
  "description": "Draws a new diagram from a description; sends it to an LLM service",
  "interpreter": "python3",
  "parameters": [
    { "id": "prompt", "type": "text", "label": "Description", "scope": "run",
      "required": true, "language": "markdown" },
    { "id": "model", "type": "string", "label": "Model", "scope": "persistent",
      "default": "deepseek-flash" },
    { "id": "url", "type": "string", "label": "Server", "scope": "persistent",
      "default": "https://api.deepseek.com/v1" },
    { "id": "key", "type": "secret", "label": "API key", "scope": "persistent",
      "default": "env:DEEPSEEK_API_KEY", "export": "HSM_MAKER_KEY" }
  ],
  "actions": [
    { "id": "draw", "label": "Draw a new diagram...", "result": "new-document",
      "toolbar": true, "icon": "icons/draw.svg", "timeout": 300,
      "argv": ["-m", "hsm_maker", "-f", "${param-file:prompt}", "-o", "${output}",
               "--model", "${param:model}", "--url", "${param:url}",
               "--key-env", "HSM_MAKER_KEY"] }
  ]
}
```

`hsm-maker` завершается с кодом 0, если диаграмма создана, 1 — если нет, 2 — при ошибке
использования и 3 — при ошибке сервера; успехом считается только 0, а остальное
объясняет её stderr.

### Компилятор на сервере

`lapki-compiler` — сервер WebSocket, поэтому его плагин — адаптер: он берёт адрес сервера
из параметра `persistent`, отправляет `${input}` на `ws://<сервер>/main`, записывает
полученные исходные тексты и двоичные файлы в `${outdir}`, выводит журналы сборки и
завершается с ненулевым кодом при неудачной сборке. Платформа берётся из метаинформации
документа (`${meta:platform}`). Адаптер, запускающий локальный сервер, останавливает его
перед своим завершением.

## Контрольный список

* Никаких окон и вопросов через stdin: объявляйте параметры.
* Пишите только объявленные выходы; не трогайте `${input}` и каталог плагина.
* UTF-8 в stdout и stderr; одна понятная строка на ошибку.
* Осмысленные коды завершения и `exit_ok` со списком успешных.
* Останавливайте каждый запущенный вами процесс.
* Никогда не выводите секрет.
* Указывайте в `description`, если документ покидает машину.
* Держите `i18n/<язык>.json` в согласии с английскими текстами: изменённый текст теряет
  перевод, пока файл не обновлён.
